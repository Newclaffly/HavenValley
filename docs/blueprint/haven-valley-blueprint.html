Heightmap เดียวเป็นต้นฉบับ

Heightmap ภาพขาวดำ 16-bit ขนาด 1024 × 1024 px ที่ 1 ม. ต่อพิกเซล ครอบคลุม X/Z −512…512 (พื้นที่เล่นได้ 1000 ม. บวกขอบ 12 ม.) การเข้ารหัสความสูง: Y = −20 + ค่า × 200 / 65535 ได้ความละเอียด 3 มม. ตั้งแต่ Y −20 ถึง 180 การปั้นทำบนไฟล์นี้หรือใน editor อย่างใดอย่างหนึ่ง ไม่ทำสองที่

ตัวเรนเดอร์ภูมิประเทศ (ตัดสินใจแล้ว: Terrain3D)

ใช้ add-on Terrain3D (GDExtension ของบุคคลที่สาม) ซึ่งนำเข้า heightmap ให้ปั้นและระบายเลเยอร์เท็กซ์เจอร์ใน Godot ได้ และมีระบบ LOD และ collision ในตัว รุ่นล่าสุด (v1.0.2) ระบุว่ารองรับ Godot 4.4–4.6+ แต่ยังไม่ยืนยันสำหรับ 4.7 งานแรกของ Phase 1 จึงเป็นการทดสอบความเข้ากันได้กับ Godot 4.7.2 แผนสำรอง: ปั้นใน Blender แบ่งเป็น 64 ชิ้น export เป็น GLB และสร้าง collision จาก heightmap เดียวกันด้วย HeightMapShape3D

เลเยอร์เท็กซ์เจอร์

8 เลเยอร์: หญ้า หญ้าทุ่ง พื้นป่า ดินฟาร์ม ถนนดิน หินปูถนน หิน ก้นแม่น้ำ/ทะเลสาบ ถนนถูกระบายลงในเลเยอร์เหล่านี้ และรูปทรงถนนยังเก็บไว้ในฉากเป็นโหนด Path3D เพื่อให้เส้นทาง NPC และแผนที่ในเกมใช้ข้อมูลชุดเดียวกัน

นอกขอบโลก

โมเดลฉากหลังแบบโพลิกอนต่ำออกไปประมาณ 1.5 กม. ไม่มี collision: เงาภูเขาทางเหนือ กำแพงป่าจาก tree card ทางตะวันตก เนินเขาทางตะวันออกและใต้ หมอกช่วยซ่อนจุดสิ้นสุด ขอบพื้นที่เล่นถูกกั้นด้วยภูมิประเทศเอง (หน้าผา ทางลาดป่าชัน เนินเขา) และมีกำแพงล่องหนบางๆ เป็นตัวสำรองเท่านั้น

แหล่งน้ำ

แม่น้ำและลำธารเป็นโมเดลแบบริบบิ้นที่ทำใน Blender ตามเส้นโค้งที่ล้อตามเส้นทางด้านบน โดยให้ UV.y วิ่งตามทิศน้ำไหล spatial shader ตัวเดียวเลื่อน normal และฟองตาม UV.y และวาดฟองขาวตามขอบเหมือนภาพอ้างอิง โดยเทียบความลึกของฉาก (sampler hint_depth_texture) กับผิวน้ำ ทะเลสาบเป็นโมเดลแบนที่ Y 0 ใช้ shader เดียวกันโดยไม่มีการไหล

ถ้ำและเหมือง

ปากถ้ำเป็นโมเดลหน้าผาจาก Blender ภายในถ้ำเป็นโมเดลแยกอยู่ด้านหลัง ผู้เล่นเดินเข้าไปได้เลยจึงไม่มีหน้าจอโหลด เจาะรูภูมิประเทศ (terrain hole) ของ Terrain3D ใต้ปากถ้ำ

พืชพรรณและพร็อพ

ของตกแต่ง (ต้นไม้ พุ่มไม้ หิน ดอกไม้ หญ้า) ใช้ MultiMeshInstance3D หนึ่งตัวต่อชนิดต่อ chunk และค่อยๆ หายไปตาม visibility_range_end: ต้นไม้ 250 ม. พุ่มไม้ 100 ม. หญ้า 45 ม. สิ่งใดที่ผู้เล่นตัด ขุด หรือเก็บได้ จะเป็น scene instance จริงที่มี ID ถาวร

ID ถาวรและการบันทึกเกม

รูปแบบ region.type.chunk.index เช่น forest.tree_oak.B4.0031 เครื่องมือใน editor กำหนด ID ครั้งเดียวแล้วเก็บไว้ในฉาก เซฟเกมบันทึกเฉพาะสิ่งที่เปลี่ยนจากฉากต้นฉบับ (ต้นไม้ที่ถูกตัด หินที่ถูกขุด อาคารที่วาง) เกมใหม่จึงเป็นรายการเปลี่ยนแปลงว่างเปล่า

การติดตาม chunk

WorldManager คำนวณ chunk ของผู้เล่นจากตำแหน่งทุก physics tick และส่ง EventBus.chunk_changed ขอบเขต Area3D ของแต่ละภูมิภาคควบคุมเสียงบรรยากาศและป้ายชื่อบนแผนที่ ถ้าวันหนึ่งต้องทำ streaming ก็ใช้ดัชนี chunk เดียวกันนี้ตัดสินว่าจะโหลดอะไร
